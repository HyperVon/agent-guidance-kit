# PR #214 — Harden user lookup

**Branch:** `fix/user-lookup-npe` → `main`
**Author:** directory team
**Tracking:** INC-4471

## Summary

Login was returning `500` for a small set of older accounts (see
`docs/runbook-login-errors.md`, INC-4471). The profile read path raised a
`TypeError` / `AttributeError` out of `users.get_user_profile` and that
propagated all the way to the HTTP layer.

This PR hardens the lookup so a bad profile read can no longer take down the
login response, adds a warning log with the affected `user_id` so the backfill
team can track the remaining gap, and extends
`GET /internal/session-context` so the support console can tell whether a
profile was present.

## Changes

- `users.py` — guard the profile materialization path
- `auth.py` — touched during the investigation
- `app.py` — report `profile_present` on the session-context endpoint
- `validation.py` — add `clamp_page_size` for the upcoming directory paging work
- `tests/` — cover the missing-profile and null-`display_name` cases

## Verification

- `python -m pytest -q` locally
- Manually curled `POST /login` against a seeded pre-backfill account; no more
  `500`
