# Support

## Before opening an issue

Review the [README](README.md), the [adoption prompt](docs/adoption-prompt.md),
and its [prompt cookbook](docs/adoption-prompt.md#common-maintenance-prompts) for
the documented workflow. Search existing issues before creating a duplicate.

## Where to ask

- Use the bug report form for reproducible behavior that conflicts with a
  documented contract.
- Use the improvement proposal form for focused additions or workflow changes.
- Use a blank issue for a question that does not fit either form.
- Report vulnerabilities through [GitHub's private security advisory flow](SECURITY.md).

Never include credentials, private repository content, personal paths, or other
sensitive data in a public issue.
